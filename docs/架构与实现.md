# 架构与实现

本页对应 **2.2.19**。

## 交付结构

- `src/catalog.js`：目录校验、旧格式读取、无损合并和模型发现。
- `src/storage.js`：宿主存储适配、持久化与账户快照。
- `src/panel.js`、`src/panel-editor.js`、`src/panel.css`：主工具栏、折叠列表、弹窗及编辑表单的界面层。
- `src/panel-theme.js`：解析宿主外观、应用管理器配色及维护透明度预览。
- `src/connection.js`、`src/bootstrap.js`：显式应用及扩展入口。
- `src/form-fill.js`：从当前可编辑的 API 地址或密钥输入框打开配置选择器。只写选定字段与同作用域内可唯一配对的字段，使用原生输入事件交还给目标插件处理。只监听焦点和点击，在进入过的开放 Shadow DOM 内补充焦点监听。聊天输入区直接排除，不检查输入内容。
- `tools/build.cjs`：从以上源码生成根 `index.js` 与旧 iframe 兼容构建。原生版挂在当前窗口，兼容构建仅使用已初始化的父窗口；二者共用管理逻辑。
- 根 `manifest.json` 指向 `index.js`。兼容目录的五个历史 JSON 仍固定到原历史提交。

旧上游构建可在 Git 历史中查阅。旧 Vue 样式中用于工具栏、弹窗、配置行和表单的规则已移到独立的样式文件。构建读取当前源码及样式，相关许可证保留在仓库中。

主面板与各级子弹窗使用相同的外框样式，统一移除外阴影。主题默认跟随宿主明暗和底色，也支持手动切换日间、夜间。跟随宿主时可调节 0% 至 30% 的管理器弹窗底色透明度，默认 0%。手动日间、夜间使用实底。主面板和填入窗口的分组标题都用正文色，标签自定义颜色通过分组色条及色点体现，已选品牌图标继续展示。弹窗底色和标签色条颜色在各自元素上生效，优先于主题的通用规则。遮罩点击只关闭当前弹窗。按下和点击都必须发生在弹窗外，保存等操作进行时暂缓关闭。

扩展表单填写独立于聊天的「应用」操作。填写以可访问的网页输入框为准。跨域 iframe、封闭的 Shadow DOM 和不公开输入框的插件需要使用各自的设置方式。

填写窗口复用目录标签与组内顺序，搜索展开命中组。折叠状态只影响当次窗口。打开填写窗口时会检查已配对地址和密钥所在表单的模型和附加参数字段。模型名需已保存，并且表单内有唯一可编辑、可见的模型输入框。可唯一确认的主体与排除字段按表单要求写入 JSON、分行列表或 YAML 原文。空白配置保留目标原值，请求标头仍经原生「应用」写入。

## 数据与迁移

可选的 `row.extra` 保存包含主体参数、排除主体参数和请求标头的 YAML 原文。配置组编辑器将附加参数放在各模型卡片中，按稳定条目 ID 保存。同一密钥的其他模型保留自己的值。附加参数由「应用」写入原生自定义连接。ST 使用 `custom_include_body`、`custom_exclude_body` 和 `custom_include_headers`。TT 2.4.0 使用 `additional_parameters_by_source.custom`。没有附加参数的条目应用时会清空该自定义连接的三项值。导入旧记录可沿用已有附加参数，显式留空可清除。

目录为 `{ format: 'st-api-manager-catalog', version: 2, entries, groups }`。条目保存站点名、来源、URL、模型、密钥及分组 ID；稳定 ID 由随机数生成。编辑以 ID 定位，URL、模型或密钥变化不改变 ID，也不会更新其他条目。分组可多选，与端点和密钥没有绑定。

`modelNote` 存在模型条目上，旧 `name` 原样保留。`credentialId` 将同一配置组内共享密钥备注的模型链接到可选的 `keyNotes` 记录。首次给已有密钥加备注时，按该配置组和密钥链接同组模型。更换某条记录的密钥或端点后独立保存其密钥备注。清空备注保留空值，删除最后一个关联条目时移除相应的密钥备注记录。

合并旧文件或旧账户快照时，缺失的新字段沿用现有备注。两个版本对同一备注作出不同编辑时，合并保留双方内容并重映射对应的密钥关联。使用账户、本机或替换导入时，以用户选定的整份目录为准。

主列表使用模型 ID 和当前配置组名。旧标题保留在详情和搜索中。摘要只折叠能对上当前组或原存档记录的组名前缀，其他标记继续显示。两级备注在全宽信息区分行，条目操作在卡片底部。标签选择和卡片操作按条目 ID 定位，Key 序号用于显示同名模型对应的密钥。

卡片操作沿用 2.1.1 的图标按钮结构、宿主颜色与 5px 间距，五个操作固定同排；未分类不显示移出分组。默认隐藏排序控件，分组「排序」进入局部排序模式，底栏切换为原拖动、上下按钮及方向键操作。完成、Escape、折叠分组和关闭主面板退出模式；拖动中的 Escape 仅取消拖动。模式不写入目录。长文本就地展开，完整详情入口保留，展开状态在关闭面板时清空。卡片非交互区域点击复用显式应用按钮；排序模式、文本选取及内部按钮不触发卡片应用。编辑按钮使用同一结构，按钮名称保留在提示和无障碍标签中。标签设置底栏使用完整文字标签，根据实际字号及按钮宽度分行。

分组由原生 `details` 展开和收起。标题避开宿主委托的 `.inline-drawer-toggle`，使宿主动画不会改写插件内容的显示状态。保存后主工具栏节点保留，返回主面板时焦点可以回到「API 管理」。[TT 2.4.0 委托逻辑](https://github.com/Darkatse/TauriTavern/blob/fff9af0333be/src/script.js#L13858)

主工具栏保留「API 管理」「检测」「设置」。标签、数据和主题从设置进入。已废弃的主面板过滤字段在读取旧设置时忽略。主题偏好记忆跟随模式、最近的手动外观，以及跟随宿主时的透明度。

展开状态保存在宿主存档的独立字段 `values.st_api_manager_ui_v1`，收起的标签使用稳定分组 ID，「未分类」使用 `null`。仅在用户改变状态时排队保存，重载后恢复。这个字段不随目录导出或账户同步，也不改变目录同步进度。入口保留魔法棒扩展菜单和斜杠命令，移除了误挂在预设区的按钮。导入方式按说明、合并选项、替换选项纵向排列；标签名称可换行，操作按钮参与正常布局。

| 宿主 | 存放位置 |
| --- | --- |
| ST | `context.extensionSettings['st-api-manager']`，宿主负责延迟落盘 |
| TT | `extension.store` 的 `st-api-manager/state`（默认 `main` 表） |

两者沿用 `{ version: 1, values }` 存档外壳。升级在 `values.st_api_manager_catalog_v2` 下写入新目录和同步进度，旧逻辑键保留原值。没有宿主存档时才读取浏览器旧键；读取失败或格式不符时停止迁移。旧版数组、分组存档及导出中的 `configStore` 都可读取。每组旧模型和密钥展开成独立条目，保留分类、密钥池位置和历史统计。已被旧版本覆盖、未留在任何存档中的密钥无法还原。

## 排序与入口

标签仍使用原有颜色字段，目录可选的 `group.icon` 仅接受 `claude` 和 `gemini`。缺省使用色点。图标随目录导出和账户同步，合并冲突可以选择任一方的颜色和图标。

标签顺序沿用目录中的 `groups` 数组。各组配置顺序保存在目录的 `groupOrders`，记录为 `{ groupId, entryIds }`；未分类使用 `null`。没有排序字段的旧目录沿用原有条目顺序。排序属于目录数据，随导出、替换导入和账户同步保存；合并保留本机顺序，并按传入顺序追加新记录。配置内容与排序分开比较，同一配置属于多个标签时可分别排序。

入口选择存于当前酒馆的 UI 字段，不写入目录导出或账户同步。ST 的扩展设置由当前酒馆服务器保存，同一宿主账户在不同浏览器中可能共享该偏好；TT 沿用扩展存储。默认保留魔法棒，可改为 QR 或同时启用。QR 通过宿主公开的 Quick Reply API 建立独立入口，不覆盖已有 Quick Reply 集合，也不自动改变宿主 Quick Reply 的全局启用设置。QR 暂不可用时保留魔法棒，斜杠命令始终可用。

## 导入与同步

JSON 导入先按 ID 比较记录。同一 ID 出现不同内容时，目录为传入版本分配独立 ID，并记录它的来源 ID。只有来源 ID 和内容都相符，重复导入才会沿用该冲突副本。分组使用同一规则，条目会引用合并后对应的分组。来源 ID 随目录一同保存、导出和同步。旧文件中缺少条目 ID 的记录按完整内容匹配。格式无效时拒绝整次导入。

账户同步走宿主公开的 `accountStorage`。旧 `st_api_manager_sync_v1` 仅作为读取来源，新版本手动写入 `st_api_manager_sync_v2`。发生冲突时，使用账户数据会替换本机目录，使用本机数据会覆盖账户目录，合并会写回两端。取消不写入。合并可选择同名标签的颜色和图标，同时保留独立标签 ID 和条目归属。执行选择前会重新读取账户快照并检查本机目录，发现变化时需重新打开弹窗。这个检查以宿主可读取的快照为准，不是跨设备原子锁。

回退时先导出新版目录保留本次新增内容，再使用旧版代码读取原有逻辑键和旧账户快照。旧版不会读取新版编辑。

## 模型发现与聊天隔离

拉取模型向表单指定的站点发送 GET 请求。发起请求时锁定所选密钥，未选时使用表单列表第一把。每把密钥各自保留可用模型、已选模型和标签。更改密钥、端点或来源会废弃相应的旧请求。拉取失败时保留已选模型、已有候选及保存的配置。检测使用同一模型接口；发送测试消息由所选站点和模型直接处理。直连受站点的跨域策略约束。

条目的「应用」是唯一写入宿主连接设置和密钥的界面入口。ST 原生应用前刷新宿主密钥缓存，TT 由自身连接流程读取密钥。应用保持旧版的自定义兼容、OpenAI、DeepSeek 和 Google AI Studio 映射，缺少模型或密钥时先提示补齐。新增、保存、检测、拉取、测试消息、导入和同步都与这条应用路径分开。

旧存档中的密钥池关系和统计继续随目录保留。应用时只登记并激活该条目的密钥。聊天请求由宿主按当前连接处理。

## 验证

`node tools/build.cjs` 生成两个入口。Node 回归覆盖历史数据迁移、旧轮换状态隔离、子集导入冲突和账户同步。Edge 夹具覆盖 ST、TT 与旧 TT iframe。测试只访问本地夹具，使用合成密钥。手机和真实服务商尚待实测。
