# 架构与实现

本页对应 **2.2.4**。

## 交付结构

- `src/catalog.js`：目录校验、旧格式读取、无损合并和模型发现。
- `src/storage.js`：宿主存储适配、持久化与账户快照。
- `src/panel.js`、`src/panel-editor.js`、`src/panel.css`：沿用旧工具栏、折叠列表、弹窗及编辑表单的界面层。
- `src/connection.js`、`src/bootstrap.js`：显式应用及扩展入口。
- `tools/build.cjs`：从以上源码生成根 `index.js` 与旧 iframe 兼容构建。原生版挂在当前窗口，兼容构建仅使用已初始化的父窗口；二者共用管理逻辑。
- 根 `manifest.json` 指向 `index.js`。兼容目录的五个历史 JSON 仍固定到原历史提交。

旧上游构建可在 Git 历史中查阅。旧 Vue 样式中用于工具栏、弹窗、配置行和表单的规则已移到独立的样式文件。构建读取当前源码及样式，相关许可证保留在仓库中。

## 数据与迁移

目录为 `{ format: 'st-api-manager-catalog', version: 2, entries, groups }`。条目保存站点名、来源、URL、模型、密钥及分组 ID；稳定 ID 由随机数生成。编辑以 ID 定位，URL、模型或密钥变化不改变 ID，也不会更新其他条目。分组可多选，与端点和密钥没有绑定。

`modelNote` 存在模型条目上，旧 `name` 原样保留。`credentialId` 将同一配置组内共享密钥备注的模型链接到可选的 `keyNotes` 记录。首次给已有密钥加备注时，按该配置组和密钥链接同组模型。更换某条记录的密钥或端点后独立保存其密钥备注。清空备注保留空值，删除最后一个关联条目时移除相应的密钥备注记录。

合并旧文件或旧账户快照时，缺失的新字段沿用现有备注。两个版本对同一备注作出不同编辑时，合并保留双方内容并重映射对应的密钥关联。使用账户、本机或替换导入时，以用户选定的整份目录为准。

主列表使用模型 ID 和当前配置组名。旧标题保留在详情和搜索中。紧凑摘要只折叠能对上当前组或原存档记录的组名前缀，其他标记继续显示。标签选择和菜单操作按条目 ID 定位，Key 序号用于显示同名模型对应的密钥。

| 宿主 | 存放位置 |
| --- | --- |
| ST | `context.extensionSettings['st-api-manager']`，宿主负责延迟落盘 |
| TT | `extension.store` 的 `st-api-manager/state`（默认 `main` 表） |

两者沿用 `{ version: 1, values }` 存档外壳。升级在 `values.st_api_manager_catalog_v2` 下写入新目录和同步进度，旧逻辑键保留原值。没有宿主存档时才读取浏览器旧键；读取失败或格式不符时停止迁移。旧版数组、分组存档及导出中的 `configStore` 都可读取。每组旧模型和密钥展开成独立条目，保留分类、密钥池位置和历史统计。已被旧版本覆盖、未留在任何存档中的密钥无法还原。

JSON 导入先按 ID 比较记录。同一 ID 出现不同内容时，目录为传入版本分配独立 ID，并记录它的来源 ID。只有来源 ID 和内容都相符，重复导入才会沿用该冲突副本。分组使用同一规则，条目会引用合并后对应的分组。来源 ID 随目录一同保存、导出和同步。旧文件中缺少条目 ID 的记录按完整内容匹配。格式无效时拒绝整次导入。

账户同步走宿主公开的 `accountStorage`。旧 `st_api_manager_sync_v1` 仅作为读取来源，新版本手动写入 `st_api_manager_sync_v2`。发生冲突时，使用账户数据会替换本机目录，使用本机数据会覆盖账户目录，合并会写回两端。取消不写入。合并可选择同名标签的颜色，同时保留独立标签 ID 和条目归属。执行选择前会重新读取账户快照并检查本机目录，发现变化时需重新打开弹窗。这个检查以宿主可读取的快照为准，不是跨设备原子锁。

回退时先导出新版目录保留本次新增内容，再使用旧版代码读取原有逻辑键和旧账户快照。旧版不会读取新版编辑。

## 模型发现与聊天隔离

拉取模型向表单指定的站点发送 GET 请求。发起请求时锁定所选密钥，未选时使用表单列表第一把。每把密钥各自保留可用模型、已选模型和标签。更改密钥、端点或来源会废弃相应的旧请求。拉取失败时保留已选模型、已有候选及保存的配置。检测使用同一模型接口；发送测试消息由所选站点和模型直接处理。直连受站点的跨域策略约束。

条目的「应用」是唯一写入宿主连接设置和密钥的界面入口。ST 原生应用前刷新宿主密钥缓存，TT 由自身连接流程读取密钥。应用保持旧版的自定义兼容、OpenAI、DeepSeek 和 Google AI Studio 映射，缺少模型或密钥时先提示补齐。新增、保存、检测、拉取、测试消息、导入和同步都与这条应用路径分开。

旧存档中的密钥池关系和统计继续随目录保留。应用时只登记并激活该条目的密钥。聊天请求由宿主按当前连接处理。

## 验证

`node tools/build.cjs` 生成两个入口。Node 回归覆盖历史数据迁移、旧轮换状态隔离、子集导入冲突和账户同步。Edge 夹具覆盖 ST、TT 与旧 TT iframe。测试只访问本地夹具，使用合成密钥。手机和真实服务商尚待实测。
