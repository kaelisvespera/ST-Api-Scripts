# ST-Api-Scripts

SillyTavern（ST）与 TauriTavern 2.4（TT）的 API 配置管理器。本文对应 **2.2.29**。

## 使用

原生扩展通过酒馆的「扩展 → 安装扩展」安装，地址为 [kaelisvespera/ST-Api-Scripts](https://github.com/kaelisvespera/ST-Api-Scripts)。升级时先停用旧 API 管理器脚本，再刷新酒馆。原有配置无需删除。通过魔法棒扩展菜单的「API 管理」打开，也可使用 `/st-api-manager`。在「设置 → 数据 → 入口设置」选择魔法棒、QR（Quick Reply）或同时启用。QR 使用酒馆的 Quick Reply 功能；该功能不可用或未启用时，魔法棒入口会保留。

- 主面板提供「API 管理」「检测」和「设置」，配置按标签折叠展示。每个分组和「未分类」的展开状态保存在当前酒馆，重启后恢复。通过「API 管理」可新增或编辑一个站点的多把 Key 和多个模型。点击遮罩返回上一级。在主面板点击遮罩会退出管理器。
- 主面板搜索支持模型 ID、原条目标题、模型备注和密钥备注。只显示命中的配置及其标签分组，清空搜索恢复原来的折叠状态。
- 在「设置」开启「固定当前应用标签」，从标签分组应用模型后，原分组标题条固定在搜索栏下方，仍可排序和展开或收起卡片。模型卡片继续按标签设置里的分组顺序滚动。默认关闭。
- 在「标签设置」拖动排序柄，可调整主界面标签分组顺序。在主界面点分组旁的「排序」，底栏切换为拖动排序柄和上移、下移按钮，也支持方向键。每次移动自动保存，点「完成」或按 Escape 退出；拖动过程中按 Escape 只取消本次拖动。排序会保存，同一配置在多个标签中的顺序分别记录。
- 「拉取模型」使用表单当前选中的 Key，未选时用列表第一把。每把 Key 各有模型列表，可多选模型并为每条配置选标签。同 URL、同模型下的不同 Key 独立保存。站点若限制跨域访问，可手动填写模型。
- 在密钥掩码下方填写「密钥备注」，在各个模型 ID 下方填写「模型备注」。例如给一把 Key 写「CCMAX」，再给它下面的某个模型写「0.5/次」。同一配置组内同一条密钥记录的模型共享密钥备注，每条模型各自保存模型备注。清空后点「保存」可移除备注。旧「条目备注」仍可在单条编辑中使用。
- 卡片上方显示模型、当前组名和两级备注。组名与备注同字号，长内容默认收起为一行。卡片有截断的文字、换行备注或未显示的原标题时，点模型名或右侧箭头一次即可展开。短卡片直接显示全部信息。五个原有图标按钮集中在底部同一排，未分类卡片沿用四个适用操作。日常模式可点卡片空白处快速应用。展开的信息可直接选取和复制。当前应用的卡片有绿色边框、浅层底色和「✓ 已应用」标记。默认跟随 ST／TT 的底色、文字色与强调色，并调整对比度以保持可读。分组标题使用独立的主题底色与细边。分组名和计数采用正文色，自定义标签的原色保留在带轮廓的色条和色点中。TT 桌面宽窗口会拉开分组色标、文字和操作按钮的间距。
- 「设置 → 主题设置」可关闭跟随模式并选择「日间」或「夜间」。开启跟随模式时可即时预览并保存 0% 至 30% 的面板透明度，默认 0%。透明度只作用于管理器弹窗底色。手动日间和夜间均使用实底。
- 「设置 → 标签设置」可按当前组名、模型 ID、原条目标题和两级备注搜索。同组同名模型会显示 Key 序号，便于选中对应密钥的条目。新建或编辑标签时可在颜色旁选择色点、Claude 或 Gemini 图标。颜色可单独调整，图标会显示在分组标题和标签选择列表中。长标签名称自动换行，编辑和删除按钮分别占位。底部操作仅用文字，宽度不足时整组换行。
- 「检测」和「发送测试消息」直接请求指定站点。测试消息需要先选定表单中的 Key 和模型。
- 「设置 → 数据」可配置入口、导出、导入与账户同步。导入可选择合并或替换，支持旧版数组和分组导出。账户冲突时可以使用账户数据、使用本机数据、合并或取消。合并保留独立副本，可选同名标签的颜色和图标。导出文件和账户存档包含密钥及已保存的附加请求标头，请按私有资料保存。

在其他插件的设置里点有明确名称的 API 地址或密钥字段，再点「填入 API」。选择窗口沿用主界面的标签和组内顺序，也可以搜索。有唯一配对时会同时填写地址和密钥，同一表单里有明确的模型输入框时也会填入已保存的模型名。单字段表单可单独填写。一个表单里有多组地址或密钥且无法确认配对时，先打开只包含一组的设置区。支持附加参数的表单会一并填入已设置的主体参数和排除项。界面使用 JSON 时会自动转换，使用 YAML 时保留原文。未设置的字段保留插件里的原值。最后按目标插件自己的流程保存。

编辑「自定义（兼容 OpenAI）」配置时，在「模型列表」里展开对应模型卡片的「附加参数」。每个模型独立保存包含主体参数、排除主体参数和包含请求标头。包含主体参数和包含请求标头使用 YAML 对象，排除项使用 YAML 字符串数组。保存后，在主界面点该条目的「应用」才会写入原生连接。切换到没有附加参数的自定义条目会清空上一条的三个字段。

2.2.2 移除了编辑页的 Key 轮换开关和聊天时自动换 Key。配置编辑、导入、同步和模型拉取只管理目录。

## 数据与验证

旧站点、分组和密钥池按独立条目迁移。原始存档和旧账户快照保留，可用于回退；新版编辑不会写回旧快照。实现和恢复方式见 [架构与实现](docs/架构与实现.md)。

```sh
node tools/build.cjs
node --experimental-vm-modules --test tests/*.test.cjs
node --test tests/*.browser.cjs
```

本地通过 59 项 Node 回归和 71 项 Edge 浏览器测试。2.2.10 曾以 ST、TT 原生及旧 TT iframe 三种夹具验证了实际上游 Quick Reply API 与集合类。浏览器验收使用 ST、TT 和旧 TT iframe 的隔离夹具，覆盖拖动、触摸与边缘自动滚动、取消、保存失败重试、组内排序、重载与账户同步，以及 QR 入口切换、延迟加载和用户集合保护。既有编辑返回、分组展开、导入和长标签排版回归保持通过。视口包含 320px 手机、平板、横屏和桌面。手机和真实服务商尚待实测。原生安装无需酒馆助手，五个旧导入 JSON 对应历史脚本版本。
